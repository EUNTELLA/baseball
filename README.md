# 목표 좌표 기반 투수 제구력 평가 시스템

스트라이크존 안에 지정된 목표 좌표와 실제 투구가 도달한 좌표를 비교하여 투수의 제구력을 정량적으로 평가하는 프로젝트입니다.

단순한 스트라이크 비율만으로 제구력을 판단하지 않고, 목표 지점에 대한 **정확도**, 반복 투구의 **일관성**, 허용 범위 안에 들어온 **유효 투구율**을 함께 분석합니다.

## 프로젝트 목표

- 스트라이크존과 목표 지점을 2차원 좌표로 표현
- 목표 좌표와 실제 투구 좌표 사이의 오차 계산
- 투구의 정확도와 반복 일관성을 수치화
- 목표별·구역별 제구 성과 비교
- 분석 결과를 스트라이크존 차트와 대시보드로 제공

## 평가 방식

### 1. 좌표 체계

- `x`: 포수 시점 기준 스트라이크존의 좌우 위치
- `y`: 지면으로부터 공이 통과한 높이
- `(target_x, target_y)`: 투수가 던져야 하는 목표 좌표
- `(actual_x, actual_y)`: 실제 투구가 도달한 좌표

좌표의 단위와 원점은 데이터 수집 방식에 맞춰 하나로 통일합니다. 초기 MVP에서는 스트라이크존의 중심을 `(0, 0)`으로 두고 정규화한 좌표를 사용합니다.

### 2. 거리 오차

목표 좌표와 실제 좌표 사이의 유클리드 거리를 투구 오차로 사용합니다.

```text
distance_error = √((actual_x - target_x)² + (actual_y - target_y)²)
```

평균 거리 오차가 작을수록 목표 지점에 정확하게 던진 것으로 평가합니다.

### 3. 주요 평가 지표

| 지표 | 의미 | 평가 기준 |
| --- | --- | --- |
| 평균 거리 오차 | 목표점과 실제 투구점 사이의 평균 거리 | 작을수록 우수 |
| RMSE | 큰 제구 실수에 더 큰 가중치를 둔 오차 | 작을수록 우수 |
| 일관성 | 실제 투구 좌표가 퍼진 정도 | 표준편차가 작을수록 우수 |
| 유효 투구율 | 허용 반경 안에 들어간 투구의 비율 | 높을수록 우수 |
| 스트라이크존 적중률 | 실제 투구가 유효한 존 안에 들어간 비율 | 높을수록 우수 |

```text
valid_pitch_rate = 유효 반경 이내 투구 수 / 전체 투구 수 × 100
```

### 4. 종합 제구력 점수

초기 가중치는 다음과 같이 적용하고, 실제 데이터 분포를 확인한 뒤 조정합니다.

```text
control_score =
    accuracy_score × 0.5
  + consistency_score × 0.3
  + valid_pitch_score × 0.2
```

각 세부 점수는 서로 비교할 수 있도록 `0~100` 범위로 정규화합니다. 투구 수가 너무 적은 선수는 점수가 과대평가되지 않도록 최소 표본 수를 별도로 설정합니다.

## 입력 데이터

MVP에서 한 번의 투구는 다음 필드를 가집니다.

| 필드 | 설명 | 예시 |
| --- | --- | --- |
| `pitch_id` | 투구 고유 ID | `P0001` |
| `pitcher_id` | 투수 고유 ID | `KIM01` |
| `pitched_at` | 투구 시각 | `2026-07-28T19:30:00+09:00` |
| `target_x` | 목표 x 좌표 | `-0.6` |
| `target_y` | 목표 y 좌표 | `0.5` |
| `actual_x` | 실제 x 좌표 | `-0.52` |
| `actual_y` | 실제 y 좌표 | `0.41` |
| `zone_width` | 해당 투구에 적용한 존 너비 | `2.0` |
| `zone_height` | 해당 투구에 적용한 존 높이 | `2.0` |
| `pitch_type` | 구종(선택) | `FASTBALL` |

실제 스트라이크존은 타자의 신장과 자세에 따라 달라질 수 있으므로, 초기에는 정규화된 고정 존을 사용하고 이후 개인별 존 보정을 확장 기능으로 추가합니다.

## 주요 기능

- CSV 또는 API를 통한 투구 좌표 입력
- 좌표 범위, 누락값, 중복 투구 검증
- 투구별 거리 오차 및 성공 여부 계산
- 투수·목표 지점·구종별 집계
- 목표점과 실제 투구 분포 시각화
- 제구력 점수 및 세부 지표 조회 API
- 선수별 결과를 보여주는 대시보드

## 시스템 구성

```text
투구 좌표 수집
      ↓
원본 데이터 저장 및 품질 검사
      ↓
거리 오차·유효 투구 여부 계산
      ↓
투수/목표/구종별 지표 집계
      ↓
API 및 스트라이크존 대시보드
```

## 프로젝트 구조

```text
baseball/
├── configs/                         # 환경 및 평가 기준 설정
├── data/                            # 원본/가공 데이터
├── doc/                             # 프로젝트 문서
├── sql/                             # 테이블 및 분석 쿼리
├── src/baseball_platform/
│   ├── collectors/                  # 좌표 데이터 수집
│   ├── transforms/                  # 오차 및 파생값 계산
│   ├── quality/                     # 데이터 품질 검사
│   ├── loaders/                     # 데이터 저장
│   ├── marts/                       # 평가 지표 집계
│   ├── api/                         # 결과 조회 API
│   └── dashboard/                   # 결과 시각화
└── tests/                           # 단위/통합 테스트
```

## 개발 로드맵

### 1단계: 평가 기준 확정

- 정규화된 스트라이크존 범위 정의
- 목표 좌표와 허용 반경 정의
- 최소 유효 투구 수와 점수 산식 확정

### 2단계: 데이터 모델 및 샘플 데이터

- 투구 원본 테이블 설계
- CSV 입력 형식 정의
- 정상·경계·실패 사례를 포함한 샘플 데이터 작성

### 3단계: 핵심 분석 기능

- 거리 오차와 RMSE 계산
- 유효 투구 및 스트라이크존 적중 여부 판정
- 정확도·일관성·유효 투구율 집계
- 계산 로직 단위 테스트

### 4단계: API와 시각화

- 투수별 평가 결과 조회 API 구현
- 스트라이크존 위 목표점과 실제 투구점 표시
- 목표별 성공률과 투구 분포 제공

### 5단계: 고도화

- 구종별 평가 및 비교
- 타자별 스트라이크존 보정
- 릴리스 포인트, 구속 등 추가 변수 분석
- 실제 경기 결과와 제구력 점수의 관계 검증

## MVP 완료 기준

- 샘플 투구 데이터를 불러올 수 있다.
- 모든 투구에 대해 목표점 거리 오차와 유효 여부를 계산할 수 있다.
- 투수별 핵심 지표와 `0~100` 제구력 점수를 제공한다.
- 스트라이크존에 목표점과 실제 투구 위치를 함께 표시한다.
- 핵심 계산 로직에 자동화 테스트가 존재한다.

## 시작하기

현재는 프로젝트 구조와 평가 기준을 설계하는 단계입니다. 첫 구현은 다음 순서로 진행합니다.

1. 좌표와 허용 반경을 담는 설정 파일 작성
2. 샘플 투구 CSV 및 데이터 검증기 작성
3. 제구력 지표 계산 모듈 작성
4. 테스트 데이터로 계산 결과 검증
5. 간단한 API와 스트라이크존 차트 구현

설치 및 실행 방법은 첫 번째 MVP 구현과 함께 추가합니다.
