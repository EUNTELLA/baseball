# 데이터 구조

이 문서는 현재 저장소의 학습·검증·추론 코드가 사용하는 공식 데이터와 파생 정보의 구조를 한곳에 정리한다. 원본 CSV의 전체 컬럼 정의는 [`open/data_description.md`](../open/data_description.md)를 기준으로 한다.

## 파일 구성

| 파일 | 크기 | 역할 | Git 포함 |
| --- | ---: | --- | --- |
| `open/data/train.csv` | 1,475,092행 × 49열 | 2019~2024 학습 입력과 정답 | 제외 |
| `open/data/test.csv` | 배포본 5행 × 48열 | 제출 코드 형식 점검용 샘플 | 제외 |
| `open/data/sample_submission.csv` | 배포본 5행 × 2열 | 제출 결과 컬럼과 순서 정의 | 제외 |
| `open/data/trackman_history.csv` | 1,793,078행 × 30열 | 2019~2024 투구 물리 이력 | 제외 |

평가 환경에서는 샘플 `test.csv`와 `sample_submission.csv`가 실제 비공개 평가 행으로 교체된다.

## 행과 정답

`train.csv`와 `test.csv`의 한 행은 한 번의 투구 직전 상태다. `train.csv`에만 이진 정답 `control_success`가 존재한다.

- `1`: 요구된 위치를 적절히 제구한 투구
- `0`: 한복판, 크게 벗어난 투구 또는 포수 요구 반대 방향 등 제구 실패

볼·스트라이크 판정과 제구 성공은 동일한 개념이 아니다. 모든 제출은 `row_id`별 `control_success` 확률을 0~1 범위로 출력한다.

## 입력 컬럼 묶음

### 식별 및 경기 정보

- `row_id`, `season`, `game_month`, `game_dayofweek`
- `inning`, `top_bottom`, `game_type`

### 투구 직전 상황

- `balls_before`, `strikes_before`, `outs_before`
- 이닝 득점과 투수 팀·홈 팀 기준 점수 차
- `runner_on_1b`, `runner_on_2b`, `runner_on_3b`
- `num_runners_on`, `base_state`
- 홈·원정 승리 기대값과 `li`

### 선수와 팀

- `pitcher_id`, `batter_id`
- `pitcher_hand`, `batter_hand`
- `pitcher_team_id`, `batter_team_id`

### 투구 직전 과거 이력

`asof_*` 컬럼은 해당 행의 투구가 발생하기 전까지 계산된 기록이다.

- 투수 누적 투구 수와 성공·실패유형·볼·스트라이크 비율
- 투수 최근 1·3·5경기 성공률과 실패유형 비율
- 투수 구종 이력량과 빠른 공·브레이킹·오프스피드 비율
- 타자 상대 이력량과 성공·실패유형 비율

현재 모델은 이 값을 그대로 사용하거나 표본 수에 따라 리그 평균 방향으로 축소한다.

## Trackman 이력

`trackman_history.csv`에는 Trackman 내부 투수 식별자, 시즌, 구종군과 다음 물리값이 포함된다.

- 구속과 홈플레이트 통과 속도
- 회전수
- 수직·수평 무브먼트
- 익스텐션
- 릴리스 높이와 측면 위치

이 파일은 `train.csv`와 행 단위로 직접 결합할 수 없다. 투수 연결과 시즌 이전 시점 집계가 필요하다. 현재 실험에서는 연결 신뢰도, 이전 시즌 수준, 물리 변화량을 검증했으나 시간 전이를 통과하지 못해 최종 1029점 모델에는 포함하지 않는다.

## 학습용 파생 정보

### 행 단위 파생 피처

[`common/model_features.py`](../common/model_features.py)가 다음 값을 생성한다.

- 표본 수를 반영한 투수·타자 성공률 축소값
- 투수·타자 손 조합
- 볼카운트 상태와 유불리
- 최근 1경기와 통산·최근 5경기의 차이
- 투수 팀 기준 홈 여부와 승리 기대값
- 투수 이력이 없는 cold-start 표시

각 값은 현재 행의 공식 입력만 사용하며 평가 행 사이의 집계를 만들지 않는다.

### 실패유형 라벨

[`common/failure_labels.py`](../common/failure_labels.py)는 공식 Train 안에서 같은 투수의 다음 누적 상태가 정확히 한 투구 증가한 경우에만 `middle`, `reverse`를 복원한다. 복원되지 않은 행은 보조모델 학습에서 제외한다. 별도 복사 라벨 파일은 저장하지 않는다.

### 잔차 차등표

현재 최고 모델은 과거 시즌 OOF 잔차에서 다음 투수별 조건 차이를 계산해 학습 자산으로 저장한다.

- 같은 손 타자 상대
- 2스트라이크 상황
- 주자가 있는 상황

평가 시에는 Train에서 저장한 표를 현재 행의 `pitcher_id`와 조건으로 조회하며, 평가 데이터의 다른 행은 사용하지 않는다.

## 시간 검증 구조

무작위 분할 대신 시즌 전방 검증을 사용한다.

```text
2019~2021 학습 → 2022 검증
2019~2022 학습 → 2023 검증
2019~2023 학습 → 2024 검증
2019~2024 전체 학습 → 2025 평가
```

잔차표나 보정 계수도 검증 연도보다 앞선 시즌에서만 생성한다.

## 평가 및 독립 예측 원칙

Brier Skill Score는 확률과 정답의 제곱오차를 시즌 정답률 기준 상수예측과 비교한다. 순위만 맞히는 것이 아니라 확률의 크기와 평균 편향이 모두 중요하다.

평가 시 허용되는 정보는 다음으로 제한한다.

- 현재 평가 행의 공식 입력
- 공식 Train으로 미리 학습한 모델
- 공식 Train으로 미리 계산해 제출 ZIP에 저장한 상수와 조회표

평가 데이터 전체의 평균, 선수 빈도, rolling, 누적 통계 또는 분포를 이용한 보정은 사용하지 않는다.
